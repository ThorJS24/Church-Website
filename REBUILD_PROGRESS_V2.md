# Frontend Rebuild V2 — Progress Log

Second complete frontend rebuild, on branch `redesign/warm-rebuild` off `main`. See the approved plan for full context and phase list. This rebuild replaces the first one (`redesign/design-system`, already merged to `main`, documented in `REBUILD_PROGRESS.md`) — the user explicitly rejected that result as "too plain / cold / corporate" and asked for a full teardown, not an iteration.

Direction: **Warm & traditional-modern** — deep navy primary, antique gold secondary, warm ivory/espresso neutrals (not zinc), Fraunces serif + Figtree sans, shadcn/ui (Radix primitives) as the component foundation, Tailwind v4.

## Phase 0 — Foundation & dependency swap: IN PROGRESS

### Done
- New dependencies installed: `motion`, `cmdk`, `sonner`, `@tanstack/react-table`, `class-variance-authority`, `tw-animate-css`, the individual `@radix-ui/react-*` primitives, `shadcn` CLI (v4.16.1), `radix-ui`.
- Ran `npx shadcn@latest init` (`--base radix --preset nova`) — `components.json` created.
- **Renamed the entire first-rebuild `components/ui/` library (27 files) to `components/ui-legacy/`** and updated all 81 import sites across `app/`, `components/`, `lib/`. This was necessary, not optional: this filesystem is case-insensitive, so shadcn's kebab-case `button.tsx` silently overwrote the hand-rolled `Button.tsx` on first `init` (same file on disk) — confirmed by `git diff` showing the original component's content replaced. Restored from git, then did the rename instead of relying on case-based coexistence. `components/ui-legacy/*` stays wired to everything not yet rebuilt; `components/ui/*` is exclusively new shadcn/hand-rolled-layout-primitive territory going forward. Final cleanup phase deletes `ui-legacy` once nothing imports from it.
- Fixed `shadcn init` silently overwriting a pre-existing `lib/utils.ts` (which held `extractYouTubeId`/`getYouTubeEmbedUrl`, used by the sermons pages) with its own `cn()`-only version — merged both; `lib/utils.ts` now re-exports the real `cn()` from `lib/cn.ts` (which has a load-bearing `tailwind-merge` class-group fix for this app's named font-size scale) plus keeps the YouTube helpers.
- **Migrated Tailwind v3.4 → v4.** The plan originally said "stay on v3.4" on the assumption shadcn/ui still supported v3. That assumption was wrong: the current shadcn CLI generates every component against Tailwind-v4-only CSS (`@theme inline`, `@utility`, `--value()`) with zero v3 support. Confirmed shadcn 3.x (a v3-compatible major) is still published, presented both options to the user, who chose migrating to v4 (see the plan file's "REVISED 2026-08-05" note). Used the official `npx @tailwindcss/upgrade` codemod, which correctly converted the entire `tailwind.config.js` (colors, fontSize scale, radius, shadow, duration/easing, animations, breakpoints) into a CSS-first `@theme` block in `app/globals.css`, preserving the existing `:root`/`.dark` CSS-custom-property architecture untouched (only the `@theme` mapping layer changed). `tailwind.config.js` no longer exists; `postcss.config.js` now uses `@tailwindcss/postcss`; `autoprefixer` removed (v4 handles this internally).
  - The codemod has a real false-positive bug worth knowing about: it blindly renamed the string literal `'outline'` → `'outline-solid'` inside two TypeScript union type definitions (`ButtonVariant`, `CardVariant` in `components/ui-legacy/{Button,Card}.tsx`) — a same-word collision with the legitimate v4 utility rename of the *CSS class* `outline` → `outline-solid`, misapplied to an unrelated component-variant name. Caught because it broke type-check immediately (all 37 `variant="outline"` usage sites failed to match the type). Fixed by reverting just those two type-union entries back to `'outline'`. Nothing else in the 35-file codemod diff triggered a similar issue (verified via a clean `type-check` run afterward).
- Rewrote the color/radius/shadow tokens in `app/globals.css`'s `:root`/`.dark` blocks with the actual warm palette (deep navy `#1D3557` primary, antique gold `#8A5E18` secondary, warm ivory/espresso neutrals, burgundy/burnt-orange/forest-green/blue-teal semantics) — see the plan file for the full color rationale. Primary hover/active/subtle/foreground shades were generated by actually running `lib/colorTheme.ts`'s `deriveAccentShades()` against the real hex (not hand-guessed), for both light and a separately-hand-chosen brighter dark-mode base (`#477ac2`), matching how the original indigo was hand-brightened for dark mode.
- Resolved a real shadcn/app naming collision: shadcn's own "accent" token means a subtle neutral hover wash (e.g. `DropdownMenuItem` hover), completely different from this app's existing `--accent` (the vivid brand color). Added a documented shadcn-compatibility alias layer in `@theme` (`--color-primary`, `--color-secondary`, `--color-muted`, `--color-destructive`, `--color-card`, `--color-popover`, `--color-ring`, etc., all pointing at the real tokens by *meaning* not by name) plus a separate `--color-shadcn-accent` for the hover-wash concept — with an operational note that every `npx shadcn add <component>` needs a follow-up grep/rename pass on any generated file using the bare `accent` class, since the collision can't be fixed by CSS variable renaming alone (the class string is baked into the generated `.tsx` source).
- Set up real fonts via `next/font/google` in `app/layout.tsx`: Fraunces (serif, weights 500/600/700 + italic) + Figtree (sans, 400-700) for the warm/traditional-modern pairing, replacing shadcn's auto-inserted Geist. Also wired real `Noto_Sans_Tamil`/`Noto_Serif_Tamil` loaders — these fixed a **pre-existing dead-config bug** from the first rebuild: `tailwind.config.js`'s `fontFamily.tamil`/`tamil-serif` referenced CSS vars (`--font-noto-sans-tamil`, `--font-noto-serif-tamil`) that were never actually defined anywhere. Removed the now-redundant manual `@font-face`/Google-Fonts-URL-import for Noto Sans Tamil.
- Wired `<MotionConfig reducedMotion="user">` around the app in `app/layout.tsx`, using the new `motion/react` package (not yet migrated: existing `framer-motion` imports across ~35+ still-unrebuilt files continue working independently until each page's own rebuild phase swaps its import — `MotionConfig` only affects `motion/react`-based components).
- Removed the redundant, fully-overridden Tailwind-v4-inserted border-color compatibility shim (this app already sets its own unlayered `* { border-color: rgb(var(--border)); }`, which always wins).
- **Found and fixed a real CSS parser bug**: straight apostrophes inside `/* */` comments (contractions like "isn't", possessives like "app's") caused Lightning CSS (Tailwind v4's toolchain) to report "Unclosed bracket" and fail the entire build with a 500. Rewrote all comment prose in `globals.css` to avoid apostrophes. Worth remembering for all future CSS edits in this rebuild.
- Removed the redundant `tailwindcss-animate` (v3-era JS plugin) package in favor of `tw-animate-css` (v4-native CSS import), which is what shadcn's own generated stylesheet expects.
- **Verified end-to-end**: `type-check` and `lint` clean; dev server boots; `/`, `/sermons`, `/gallery`, `/admin`, `/give` all return 200; confirmed via the actual compiled CSS bundle that the new warm palette (`--accent: 29 53 87`, `--background: 251 247 240`) is present and utility classes (`.bg-accent`, `.text-body-sm`, etc.) generate correctly with the v4 opacity-modifier `color-mix()` fallback pattern.
