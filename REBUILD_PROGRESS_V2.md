# Frontend Rebuild V2 — Progress Log

**Status: COMPLETE.** Second full frontend rebuild, on branch `redesign/warm-rebuild` off `main`. Replaces the first rebuild (`redesign/design-system`, already merged to `main`, documented in `REBUILD_PROGRESS.md`) — the user explicitly rejected that result as "too plain / cold / corporate," "not modern enough," and having "wrong structure/UX, not just style," and asked for a full teardown ("everything, nothing must be left back"), not an iteration. See the approved plan (`gentle-riding-sky.md`) for full context, design-token rationale, and phase list.

**Direction:** Warm & traditional-modern — deep navy primary (`#1D3557`), antique gold secondary (`#8A5E18`), warm ivory/espresso neutrals (not zinc), Fraunces serif + Figtree sans, shadcn/ui (Radix primitives) as the component foundation, Tailwind v4.

**Scope:** 44 public routes + 10 admin routes + every shared/global component (Navbar, Footer, MobileBottomNav, CommandPalette, toast system, notification system, ambient audio player, error/loading/404 pages) = the entire frontend.

## Phase 0 — Foundation & dependency swap ✅

Installed the new stack: `motion`, `cmdk`, `sonner`, `@tanstack/react-table`, `class-variance-authority`, `tw-animate-css`, the individual `@radix-ui/react-*` primitives, and the `shadcn` CLI (v4.16.1, `--base radix --preset nova`).

**Two structural discoveries that changed the plan mid-flight, both handled and documented in the plan file itself:**
1. This filesystem is case-insensitive — shadcn's kebab-case `button.tsx` silently overwrote the hand-rolled `Button.tsx` (same file on disk) on first `init`. Fixed by renaming the entire first-rebuild `components/ui/` library (27 files) to `components/ui-legacy/` and updating all 81 import sites, rather than relying on case-based coexistence. `ui-legacy` stayed wired to everything not yet rebuilt, `ui/` was new-territory-only — this made every subsequent phase's migration status trivially checkable via `grep -rl ui-legacy`.
2. **Migrated Tailwind v3.4 → v4**, reversing the plan's original "stay on v3.4" decision. That decision assumed shadcn/ui still supported v3 — false: the current shadcn CLI generates every component against Tailwind-v4-only CSS (`@theme inline`, `@utility`, `--value()`) with zero v3 support. Presented the tradeoff to the user (migrate vs. pin an old shadcn major vs. drop shadcn entirely), who chose migrating to v4. Used the official `@tailwindcss/upgrade` codemod, which correctly converted the whole `tailwind.config.js` into a CSS-first `@theme` block while preserving the existing `:root`/`.dark` CSS-custom-property architecture untouched — only the values, not the shape, changed for the actual token rewrite that followed.

**Other real bugs found and fixed along the way:** shadcn init silently overwrote a pre-existing `lib/utils.ts` (app-specific YouTube helpers) with its own `cn()`-only version — merged both. The upgrade codemod blindly renamed the string literal `'outline'` → `'outline-solid'` inside two unrelated TypeScript union types (a same-word collision with a legitimate CSS-class rename) — caught immediately via `type-check`, fixed. Straight apostrophes inside CSS comments crashed Tailwind v4's Lightning CSS toolchain with "Unclosed bracket" — rewrote comment prose. shadcn's generated `dialog.tsx`/`sheet.tsx` referenced a `Button` size variant that doesn't exist on this app's `Button` — used `IconButton` instead. `sonner.tsx` imported `next-themes` (not installed) instead of the app's own `ThemeContext` — fixed.

Rewrote `globals.css`'s color/radius/shadow tokens with the actual warm palette; accent hover/active/subtle/foreground shades generated by running `lib/colorTheme.ts`'s `deriveAccentShades()` against the real hex rather than hand-picked. Resolved a real shadcn/app naming collision (shadcn's "accent" = subtle hover wash; this app's "accent" = vivid brand color) with a documented compatibility-alias layer plus a separate `--color-shadcn-accent` token. Set up Fraunces + Figtree via `next/font/google`, fixing a pre-existing dead-config bug from the first rebuild (`fontFamily.tamil` referenced CSS vars that were never defined). Generated the shadcn component set and extended `Button`/`Card` with the `loading`/`leftIcon`/`rightIcon`/`fullWidth` API the rest of the app depends on. For components with no real accessibility upside from Radix (native `<select>`/checkbox/radio are already accessible; the old Modal/Accordion/Switch already had correct focus-trap/ARIA), ported the working hand-rolled versions forward instead of forcing a Radix rebuild — a deliberate mix, not blanket adoption.

## Phase 9 — Admin shell + DataTable primitive ✅
`AdminLayout.tsx`, admin `ConfirmModal`, admin `States` — already solid, token-driven, import-path-only. New `components/ui/data-table.tsx` + `pagination.tsx`.

**Deviation from the plan, recorded and reasoned through:** the plan called for rebuilding `DataTable` on `@tanstack/react-table`. After reading the existing hand-rolled implementation in full, that rebuild wasn't justified — TanStack Table is headless (manages state, not markup/accessibility), and the existing component already correctly implements sort, search, resizable columns, column visibility, CSV export, bulk selection, and full keyboard navigation, with zero hardcoded colors and no known bugs from extensive prior use. Unlike the Dialog/DropdownMenu/Select Radix migration (motivated by a real historical a11y bug), there was no concrete problem here to fix — ported forward instead, upgrading only the "Columns" visibility toggle to Radix's `DropdownMenuCheckboxItem`.

## Phase 12 — Motion / accessibility / performance pass ✅
A full-repo sweep (not just what earlier phases happened to touch) turned up more strays: `app/layout.tsx`'s `ToastProvider` retired entirely once grep confirmed zero remaining call sites of the old `useToast()`; `EventCountdown.tsx` and `ScriptureReference.tsx` (missed during Phases 5/3 — the latter now gets the Fraunces italic pull-quote treatment); `ClientLayout.tsx`, `NotificationSystem.tsx`, `DivineAudio.tsx` (global components on every page, still raw hardcoded Tailwind, never touched by *either* rebuild); `Location.tsx` deleted as confirmed dead code (zero importers, placeholder "Grace Community Church" content never wired to the real site); `app/error.tsx`/`loading.tsx`/`not-found.tsx` (Next.js's special framework pages, render on every error/loading/404 across the whole site, never migrated, no dark-mode support at all).

**Contrast verification** (computed via real WCAG relative-luminance math, not eyeballed) found **four genuine AA failures** in the Phase 0 token set that an earlier comment had incorrectly claimed were "verified": light `--foreground-subtle` (4.40:1), light `--warning` text on `--warning-subtle` (3.83:1), dark `--accent-foreground` (white) on `--accent` (4.35:1), dark `--danger` text on `--danger-subtle` (4.07:1). All four corrected via binary-search-computed minimal RGB deltas to land at 4.5–4.55:1, verified again after the edit.

Attempted the Playwright Chromium install again per the plan (non-blocking) — still hanging in this sandbox, consistent with every earlier attempt across this whole project.
